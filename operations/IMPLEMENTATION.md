## 검증 결과

- 전용 PostgreSQL 16·Neo4j를 사용하는 전체 테스트 132개가 통과했다. 이 테스트 실행 환경은 로컬 Python 3.13 가상환경이며, 운영 대상 이미지의 Python 3.11 검증과 구분한다. LangChain 의존성의 향후 기본값 변경 경고가 1개 남아 있다.
- 실제 자식 프로세스를 중단하고 재시작해 작업 인계와 시도 번호 검증을 확인했다. Streamlit AppTest에서도 접수·대기 중 입력 잠금·작업자 결과 표시가 연결되는지 검사했다.
- 8개 제출 스레드·4개 처리 스레드·추론 슬롯 2개로 요청 32건을 처리했다. 모두 완료됐고 메시지는 정확히 64개, 모든 요청은 1회 처리됐다. [부하 검증의 수치와 해석 범위](README.md), [원본 수치](queue-load-result.json)를 함께 확인한다.
- 실제 pg_dump를 새 테스트 DB에 복원해 메시지·미처리 요청·Outbox·고정 프롬프트 캐시를 대조했다. 음성 파일은 원래 키로 복호화되고 다른 키로는 거부되는지 확인했다. [복구 절차](RECOVERY.md)에 AWS와 로컬 검증의 차이를 기록했다.
- CloudFormation `cfn-lint`와 `docker compose config --quiet`가 통과했다. 실제 Linux x86_64 기본·릴리스 이미지 빌드, 패키지 의존성 검사, 음성 라이브러리 로드와 LangGraph 구성도 통과했다. 네트워크가 차단된 릴리스 컨테이너에서 136,748바이트의 영어 음성을 합성하고 Whisper로 다시 인식해 영어 비어 있지 않은 결과가 나오는지도 확인했다. 이는 음성 경로 준비 검사이며 원어민 자연스러움이나 발음 정확도 평가가 아니다.

## 실제 운영에서 남은 검증

[AWS 운영 안내](../infrastructure/aws/README.md)의 네트워크, 비밀, 인증서, 외부 모델 풀과 관리형 Neo4j 조건을 먼저 준비해야 한다. 템플릿이 있다고 전체 서비스의 고가용성이 입증된 것은 아니다. 실제 ECS task 종료, RDS 강제 failover, S3 권한과 장애, GPU 노드·가용 영역 중단, 시점 복구를 실행해 실패율과 복구 시간을 측정해야 한다.

이번 32건 실험은 고정 모델 응답을 사용하는 DB 큐 검증이다. 실제 LLM·GPU 처리량 향상, 동시 사용자 수, 비용 절감 수치로 해석하지 않는다. 기존 162문항의 대화·표현 지도 품질 평가도 이번 운영 변경 검증에서 재실행하지 않았다. 스키마 버전 변경 배포는 현재 준비 검사와의 관계를 검토해야 하며 무중단 배포를 보장하지 않는다.

실험용 `talky-ops-postgres` 컨테이너와 `talky-ops-check:local`, `talky-ops-release-check:local` 이미지는 재현을 위해 로컬에 남겨 두었다. 기존 Neo4j 평가 데이터와 다른 프로젝트의 컨테이너는 제거하거나 초기화하지 않았다.

### 평점 기반 프롬프트 변경의 활성화 경계

자동 진화는 평점에서 개선 후보를 생성해 비활성 버전으로 보관한다. 길이·역할 단어 검사는 후보 형식 검사이며 품질 인증이 아니다. 평점에는 지연·음성 인식 등 다른 원인이 섞이므로 후보 생성만으로 활성 정책을 대체하지 않는다. 후보 생성에 사용한 평가 스냅샷은 소비 처리되어 같은 자료로 후보를 무한 생성하지 않으며 부모 버전과 변경 이유를 유지한다.

자동 활성화 경로는 제공하지 않는다. 후보를 실제 배포하려면 기억 근거성·역할 유지·교정 품질의 고정 회귀셋과 별도 검증 문항에서 현재 버전과 비교하고 사람이 결과를 검토해야 한다. 통과 근거가 없는 후보는 비활성으로 유지한다. 회귀 평가를 자동으로 연결하는 후속 구현 전까지 개인화 효과나 자가 개선 성과를 주장하지 않는다.

### 고정 버전 프롬프트 캐시의 유효 기간

캐시가 활성화되면 검증된 고정 버전은 마지막 원격 확인 후 5분 동안 PostgreSQL 스냅샷에서 읽는다. 5분 이후에는 SDK 캐시를 우회해 원격 권한과 원문을 다시 확인한다. 원격의 명시적 오류(권한 거부·버전 삭제 등)는 해당 스냅샷을 무효화하고 실패하며, 일시 통신 장애에만 최대 24시간 된 스냅샷을 허용한다. label은 원격에서 버전을 결정하므로 로컬에서 임의 고정하지 않는다. 권한 철회는 다음 재검증까지 최대 5분 지연될 수 있으며 즉시 철회가 필요한 환경은 캐시를 끄고 해당 스냅샷을 삭제해야 한다. 프로젝트 또는 자격 증명을 교체할 때 기존 스냅샷은 이관하지 않는다.

캐시 사용 중에는 trace 연결을 위해 프롬프트 원문을 다시 가져오지 않고 고정 버전 참조를 metadata에 기록한다. 따라서 Langfuse 원문 연결 UI 대신 metadata의 이름과 버전을 이용해 추적한다. 반복 캐시 적중에는 쓰기가 없고 원격 재검증 시에만 검증 시각을 갱신한다.
