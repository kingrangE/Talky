# 음성 언어 재확인 첫 실험

2026-11-16 로컬 Docker, faster-whisper 1.0 계열의 small 모델, CPU int8에서 확인했다. 외부 API와 사용자 녹음은 사용하지 않았다. macOS `say`로 생성한 합성 음성 네 종류이며, 실제 한국인 영어 학습자의 발화를 대표하는 데이터셋은 아니다.

## 방식과 판단 근거

기존 방식은 자동 감지한 언어로 바로 전사한다. 개선 방식은 영어와 한국어가 경합하고 언어 확률이 0.8 미만이며 VAD로 남은 발화가 4초 이상일 때만 말소리 중간 3초를 추가 감지한다. 추가 구간에서 반대 언어 확률이 0.6 이상, 원래 언어와의 차이가 0.4 이상, 두 구간의 확률 차이 합이 0.3 이상일 때만 언어를 변경한다. 이 확률은 서로 독립적인 통계적 증거가 아니며 합산값도 보정된 신뢰 확률이 아니다. 기준은 첫 실험용으로 실제 발화에서 재검증해야 한다.

첫 실험에서는 엔진의 전사문 생성기가 언어 정보 반환 시점에 아직 실행되지 않는 점을 이용했다. 원래 언어를 유지하면 원래 생성기만 소비하고, 변경하면 선택한 언어의 생성기만 소비했다. 아래 첫 합성 측정은 짧은 후보 전사를 비교하는 후속 단계가 없는 버전의 기록이다. 오류 발생 시 원래 생성기를 유지하며 시험의 영어 고정 경로는 수정하지 않았다.

앞·중간·끝 구간을 확인한 재현 사례에서는 처음 전체 감지가 한국어 0.409, 영어 0.402였으며, 끝 3초는 한국어 0.538/영어 0.345, 중간 3초는 영어 0.652/한국어 0.201이었다. 전체 결과가 애매할 때 발화의 가장자리 대신 중간을 확인하는 첫 방식을 선택했다. 같은 사례를 보고 정한 기준이므로 독립적인 평가 결과로 해석하면 안 된다.

## 합성 입력

macOS Yuna 목소리의 한국어 문장은 “오늘은 친구와 박물관에 다녀왔어요. 주말에는 가족과 함께 여행을 갈 계획이에요.”이다. 영어 문장은 “I went to the museum with my friends yesterday. We are planning to travel together next weekend.”이며 Yuna와 Samantha로 각각 생성했다. 짧은 영어는 Samantha의 “Good morning.”이다. 음성은 AIFF로 생성하고 같은 디코더로 처리했다. 합성 파일은 임시 디렉터리에만 두고 저장소에는 추가하지 않았다.

## 관측 결과

모델을 준비한 뒤 입력마다 기존/개선, 개선/기존 순으로 두 쌍을 측정했다. 각 값은 STT 함수 실행 시간이며 음성 합성, 대화 큐 대기, LLM 응답과 TTS 생성 시간은 포함하지 않는다.

| 합성 입력 | 기존 언어 | 개선 언어 | 기존 시간(초) | 개선 시간(초) |
| --- | --- | --- | --- | --- |
| Yuna의 영어, 6.72초 | ko | en | 7.201 / 7.099 | 4.443 / 4.189 |
| Samantha의 영어, 5.28초 | en | en | 1.627 / 1.779 | 1.767 / 1.991 |
| Yuna의 한국어, 5.72초 | ko | ko | 1.758 / 1.813 | 1.539 / 1.681 |
| Samantha의 짧은 영어, 0.65초 | en | en | 1.437 / 1.291 | 1.415 / 1.337 |

Yuna의 영어는 기존 방식에서 의미가 다른 한국어 문장을 만들었고, 개선 방식에서는 합성에 사용한 영어 문장을 반환했다. 해당 사례는 초기 끝 구간/확률 0.8 기준에서 개선되지 않아 중간 구간과 결합 근거 기준으로 조정한 뒤 다시 측정했다. 나머지 세 입력은 높은 초기 확률 때문에 재확인하지 않으므로 조정 전후 같은 경로를 사용한다. 한국어 문장에는 일부 단어 전사 오류가 남았으며 언어가 유지됐다는 것이 단어 정확도 개선을 뜻하지 않는다.

이 결과는 한 오인식의 재현과 교정, 확실한 세 입력의 경로 보존을 확인한 것이다. 일반적인 정확도 향상, 평균 지연 감소, 혼합 발화 처리, 짧은 오인식 해결이나 지연 상한을 입증하지 않는다. 재확인 시간은 입력과 CPU 부하에 따라 달라지고, 모델이 높은 확률로 틀리는 경우와 4초 미만 발화는 이 방식으로 교정하지 않는다. 다음 평가는 동의하에 확보한 실제 발화의 영어→한국어 오류, 한국어→영어 부작용, WER/CER와 지연 분포를 함께 봐야 한다.

## 실제 요청에서 확인한 한계와 후속 수정

같은 날짜 사용자가 영어 자기소개가 한국어 의미 번역으로 표시된다고 보고했다. 요청한 문제 진단 범위에서 최근 녹음을 로컬로 재처리하고 저장 전사와 엔진 출력이 같은지 확인했다. 화면이나 대화 LLM이 영어 원문을 번역한 것이 아니라, 자동 감지 후 STT 엔진이 한국어 문장을 생성한 것이었다. 원본 음성이나 전사문 내용은 이 기록에 저장하지 않는다.

해당 녹음은 약 4.86초, VAD 후 약 4.2초였고 첫 감지는 한국어 0.531/영어 0.424였다. 중간 3초 감지는 영어 0.541/한국어 0.394로 뒤집혔지만 첫 기준에서는 선택을 바꿀 만큼 차이가 크지 않아 한국어를 유지했다. 따라서 위 합성 사례의 성공이 해당 실제 오류의 해결을 의미하지 않았다.

후속 방식은 두 감지가 서로 반대이며 짧은 구간의 반대 언어 확률이 0.5 이상일 때만, 그 구간의 두 후보 전사를 비교한다. temperature=0으로 추가 온도 재시도를 막고 task=transcribe를 명시한다. 후보 점수는 세그먼트별 평균 로그 확률을 토큰 수로 가중 평균한다. 토큰 수 3 미만, 빈 전사, 무음 확률 0.6 이상, 압축 비율 2.4 초과는 판단에서 제외한다. 대안 점수가 -1 이상이고 기존 후보보다 0.2 이상 높을 때만 변경한다. 언어별 토큰화가 다르므로 이 점수도 보정된 언어 정답 확률이 아니며 제한된 경험적 비교 기준이다.

실제 사례의 짧은 한국어 후보 점수는 약 -0.956, 영어 후보는 -0.706이었다. 동일한 원본을 읽기 전용으로 두 쌍 비교했을 때 기존 방식은 한국어 문장을 생성했고 후속 방식은 영어 원문 형태를 반환했다. 기존 STT는 1.902/1.564초, 개선 STT는 5.320/5.469초였다. 첫 합성 사례와 달리 이 실제 사례는 정확도 교정에 성공하면서 약 3.4~3.9초의 추가 시간이 발생했다. 확실한 언어에는 이 비교를 추가하지 않는다. 실제 단일 사례의 교정이며 전체 발화의 개선율이나 이름 철자 정확도는 검증하지 않았다. 기존 저장 기록은 수정하지 않았다.

## 두 번째 실제 사례와 적용 범위 확장

후속 수영 주제 영어 발화에서는 전체 녹음 약 12.66초, VAD 후 약 12.13초였고 첫 감지가 한국어 0.591/영어 0.127/일본어 0.253이었다. 기존의 언어 확률 차이 제한으로 재확인이 생략됐다. 중간 구간도 한국어 0.868/영어 0.084로 분류해 기존의 두 감지 불일치 조건까지 통과하지 못했다. 그러나 같은 구간의 후보 전사 점수는 영어 -0.617, 한국어 -0.803으로 영어가 더 높았다.

현재 방식은 전체 언어 확률 0.8 미만이고 4초 이상 발화에서 대안 언어 확률이 0.05 이상이면, 큰 확률 차이를 이유로 재확인을 생략하지 않는다. 짧은 구간에도 대안 언어 확률이 0.05 이상이면 두 감지 언어가 같더라도 후보 전사를 비교하며, 후보 점수 차이 기준을 0.15로 조정했다. 이미 만들어진 짧은 구간 생성기는 해당 언어의 비교에 재사용하고 다른 언어 후보만 추가 생성한다. 높은 전체 확신이나 4초 미만 발화는 여전히 이 보정 대상이 아니다.

문제 녹음을 다시 저장하거나 전사 내용을 기록하지 않고 읽기 전용으로 두 번 재처리했을 때 모두 영어로 선택됐고, 한국어 문자가 없으며 수영 주제의 영어 단어가 포함됐다. 측정 시간은 7.814초와 12.366초였으며, 모델 준비 상태와 호스트 부하를 통제한 성능 실험은 아니다. 실제 사례를 보고 조정한 경험적 기준으로서 다른 한국어 발화를 영어로 잘못 선택하는 비율, 전체 정확도와 지연 상한은 검증되지 않았다.
