# 기억 검색 기술 선택 비교

2026-11-11에 기존 개발 평가셋의 원본 144개 메시지와 90개 질문으로 PostgreSQL 원문 검색, Neo4j 원문 검색, Neo4j 그래프·원문 결합을 비교했다. 모델·프롬프트 변경을 검색 개선 효과와 분리하기 위해 이전 실험의 질문별 토픽을 고정했다. Neo4j 적재 원문이 현재 원본과 정확히 같은지 확인하고 PostgreSQL 임시 테이블에 같은 원문을 넣었다. PostgreSQL은 사용자 인덱스와 부분 문자열 가중 검색을 사용하며 tsvector나 벡터 검색 전체를 대표하지 않는다.

모든 방식에 같은 검색어 가중치와 후보 8개 한도를 적용했다. 각 문항·방식을 3회 실행해 첫 실행과 이후 반복을 기록했다. 데이터와 OS 캐시를 초기화하지 않았으므로 첫 실행을 cold latency로 부르지 않는다. 전체 810회 검색 결과와 원본 해시는 experiments/retrieval-ablation.json에 보존했다. 비용이 발생하는 AWS 자원은 생성하지 않았다.

| 방식 | Single-Hop 완전 근거 | Multi-Hop 완전 근거 | Multi-Hop 근거 회수율 | 반복 Multi-Hop p50 / p95 |
| --- | --- | --- | --- | --- |
| PostgreSQL 원문 | 24/30 | 8/30 | 52.0% | 1.502 / 5.419ms |
| Neo4j 원문 | 24/30 | 8/30 | 52.0% | 3.919 / 8.616ms |
| Neo4j 그래프·원문 | 24/30 | 9/30 | 53.3% | 7.817 / 22.007ms |

완전 근거는 질문의 정답 근거 ID를 후보가 모두 포함하는지의 지표다. 답변 정확도나 Multi-Hop 추론 성공률이 아니다. 기억 날조 30문항은 정답 근거가 없는 질문이므로 회수율을 null로 기록했으며 이를 0점 정확도로 해석하지 않는다. 토픽 추출은 고정된 결과를 재사용했으므로 이번 지연에 포함되지 않았다. PostgreSQL 단독 운영에 토픽 추출을 제거하는 설계를 적용한다면 별도 비교가 필요하다.

## 선택 문항의 실제 답변 확인

설치된 ax4-light:latest 모델, 동일 시스템·영어 답변 프롬프트, 16K 컨텍스트, temperature 0, 출력 상한 128로 세 문항의 원문·그래프 결합 답변 6개를 생성했다. 후보는 양쪽 모두 원본 ID 순서로 정렬해 전달했다. PostgreSQL과 Neo4j 원문 검색의 후보가 같은 조건은 대표 원문 방식 한 번만 생성했다. 원문과 usage·지연은 experiments/retrieval-answers.json에 보존했다. 이는 에이전트가 참조 정답과 읽어 비교한 진단이며 독립 judge 점수나 사람 검수를 완료한 평가가 아니다.

- s1-sh01: 두 방식 모두 연남동과 작은 가게라는 원본 사실을 반영해 같은 답변을 생성했다.
- s2-mh04: 원문 검색에는 Elena와 Northwind Studio 관계만 있었고, 모델은 해외 파트너가 맞는지 확인했다. 그래프 결합에는 Northwind Studio가 해외 파트너라는 추가 근거가 있어 Elena를 답했다. 이 문항은 여러 근거 연결의 유효성을 보여주는 사례지만 전체 데이터에서 1문항의 차이다.
- s2-ha01: 두 방식 모두 급여를 지어내지는 않았지만 '기록에 없으니 금액을 알려 달라'는 기대 행동 대신 개인정보라는 이유로 답변을 거절했다. 이는 검색 방식 변경으로 해결됐다고 볼 수 없는 대화·확인 질문 품질 문제다.

## 기술 선택과 남은 판단

이번 자료에서는 PostgreSQL 원문 검색이 더 빠르고 두 원문 검색의 근거 회수는 같았다. 그래프 결합은 Multi-Hop 완전 근거를 1문항 더 회수했지만 추가 DB, Outbox, 백업·복구 비용을 전체적으로 정당화할 만큼 충분한 증거는 아니다. 반대로 필요한 연결 근거를 추가로 찾은 사례가 있으므로 즉시 그래프를 제거하는 결정도 이 실험만으로 확정하지 않는다.

현재 선택은 Neo4j를 유지하되, '그래프이므로 Multi-Hop에 반드시 필요하다'는 주장을 하지 않는 것이다. PostgreSQL 원문 기준선과 그래프 없는 검색 경로를 재실행 가능하게 남겨 다음 규모의 데이터에서 퇴행 여부를 비교한다. 별도 검증 문항, 독립 답변 채점·사람 검수, 토픽 추출까지 포함한 전체 응답 지연, 데이터 증가에 따른 인덱스·DB 비용 측정 후 유지·단순화·제거를 결정한다. 이번 실험에는 금전 운영 비용 실측이 없어 숫자로 추정하지 않았다. 개발 평가셋의 결과를 일반 사용자 성능으로 확장하지 않는다.

재실행은 `python -m operations.compare_retrieval --postgres <전용_test_DB_DSN> --neo4j <전용_Neo4j_URI> --run <토픽이 저장된_평가_디렉터리>`로 수행한다. 선택 답변은 같은 환경에서 `MODEL_NAME=ax4-light:latest python -m operations.check_retrieval_answers`로 생성한다. 원본이나 평가 디렉터리를 바꾸면 해시와 namespace를 함께 기록한다.
