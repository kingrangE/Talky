# A.X 기억 검색 판정의 부하·답변 품질 검증

## 목적과 비교 조건

로컬 A.X-4.0 Light의 0·1 판정이 첫 텍스트 응답을 단축하면서 기억에 근거한 답변 품질을 유지하는지 확인한다. 목표는 동시 사용자 50명, 첫 텍스트 p95 8초 이하·p99 10초 이하, 오류율 5% 미만이다. 판정기는 실험 환경에서만 활성화하며 서비스의 기본 비활성화 설정은 유지한다.

부하는 서로 다른 50개 계정에서 동시에 한 요청씩 접수한다. 일반 대화 5종과 개인 기억 질문 5종을 같은 비율로 섞고 각 계정에 과거 대화 세 턴과 현재 대화 한 턴을 먼저 저장·색인한다. 과거 대화에는 서울 거주, 고양이 Milo, 토요일 등산, 교토 여행, 기술 문제를 영어로 설명하는 학습 목표가 담긴다. 준비 단계에는 고정 토픽을 사용하며 시간 측정에서 제외한다. 측정 중에는 실제 Ollama, 교정, Piper와 PostgreSQL Outbox·Neo4j 그래프 워커를 실행한다. 생략한 발화의 지연 토픽 추출도 실제 공유 추론 슬롯을 사용한다.

기본 접수 한도 32개·판정 비활성 조건을 먼저 확인한다. 이후 실험에서만 한도를 64개로 늘려 판정 비활성·활성 조건을 같은 프로필로 비교한다. 한도 변경은 저장소의 기본 설정을 변경하지 않는다. 각 조건은 워커 네 개, 추론 슬롯 하나, 음성 슬롯 하나, 컨텍스트 16,384토큰, 최대 출력 4,096토큰, 180초 관측을 사용한다. 관측 종료 시 미완료 요청은 영구 실패와 구분하며, 텍스트가 없는 요청을 지연 분모에서 빼지 않는다. 그래프 적체·재시도와 판정 사유, 작업별 지연도 기록한다. 테스트 후 해당 실행에서 만든 사용자·대화만 삭제하고 지연 투영을 막는 삭제 표시는 유지한다.

품질 평가는 기존 데이터셋 전체를 사용한다. 기본 조건에서는 기억 90문항, 대화 12시나리오의 72개 사용자 발화, 표현 지도 60문항을 실행한다. 판정 활성 조건은 판정의 영향을 받는 기억 90문항과 대화 12시나리오를 다시 실행한다. 표현 지도는 기억 판정을 거치지 않는 독립 구성 요소이므로 한 번 평가하며 전후 비교 결과를 새로 생성했다고 표시하지 않는다. 두 조건의 프롬프트는 기존 Langfuse 버전 2로 고정하고, 답변 모델은 동일한 로컬 A.X를 사용한다. 생성 온도는 기존 평가기 기본값 0.7로 유지하므로 차이를 전부 판정기의 인과적 효과라고 단정하지 않는다.

답변 생성과 채점을 분리해 16GiB 장비에서 A.X와 EXAONE 모델을 반복 교체하는 비용을 줄인다. 생성한 원문을 저장한 뒤 로컬 `exaone3.5:7.8b`가 같은 출력을 재생 채점한다. 고정된 보정 예시 12개도 채점해 judge의 한계를 확인한다. 생성 실패와 judge 실패를 별도로 기록하고, 자동 점수에는 사람 검토가 필요하다는 기존 기준을 유지한다. 모든 모델 호출은 로컬 Ollama이며 추가 유료 모델 API를 사용하지 않는다. Langfuse에는 이미 승인된 평가 흐름에 따라 실험·출력·점수를 기록한다.

180초 관측은 첫 텍스트 목표의 실패를 확인하지만 미완료 요청의 최종 오류율을 확정하지 못한다. 품질 평가 후에는 접수 한도 64개인 두 조건을 각각 최대 600초까지 다시 관측해 완료·최종 실패·관측 시간 초과를 구분한다. 이 긴 관측에 앞서 부하 실행기도 실제 서비스처럼 종료된 대화 워커를 교체하도록 보완했다. 기존 실행기는 제한 시간 초과로 종료된 워커가 계속 빠진 상태였기 때문에 장기 부하에서 실제 서비스보다 처리 용량을 낮게 측정할 수 있었다. 워커 교체 횟수와 종료 코드를 원시 결과에 기록한다.

실제 자식 워커를 요청 접수 전에 강제 종료한 뒤 대기 요청 세 개가 교체된 워커에서 모두 완료되는 통합 검증을 추가했다. 이 보완을 포함해 별도 테스트 DB에서 전체 194개 테스트가 통과했다. 시험 중 최초 180초 부하 결과나 실제 답변·프롬프트를 바꾸지는 않았다.

## 측정 범위

부하에서 측정하는 첫 텍스트는 PostgreSQL 결과를 1초 간격으로 관측한 백엔드 지연이다. 브라우저 표시·HTTP·음성 입력 인식·AWS 배포를 포함하지 않는다. 50개의 동시 요청을 사용하는 실패 진단이며, 지속적인 50명 세션이나 충분한 p99 표본을 갖춘 최종 운영 인증으로 해석하지 않는다. 공유 Ollama에 다른 로컬 작업이 요청할 수 있어 미세한 전후 차이를 순수 모델 비용으로 해석하지 않는다. 목표 미달 여부와 어느 단계에서 대기하는지는 구분해 확인한다.

평가용 스키마가 달라도 같은 PostgreSQL 데이터베이스의 advisory lock은 공유된다. 사전 색인과 회귀 테스트가 겹쳤을 때 용량 관련 테스트가 실패한 것을 확인했으므로 같은 데이터베이스를 사용하는 실제 측정과 회귀 검증은 순차 실행한다. 품질 평가와 겹치는 추가 회귀 검증은 별도의 `talky_regression_test` 데이터베이스를 사용해 잠금 범위를 분리했다.

## 결과

실행 완료 후 원시 결과, Langfuse 실험 링크, 항목별 점수와 실패 사례를 여기에 기록한다.
